# 함께하기 (나중)

> 지금은 1인 게임. 다인은 나중에. 지금 만드는 구조가 다인 전환을 막지 않도록 지킬 점만 적는다.

## 확정 사항

- **1인 게임**이다. 다인은 서버·동기화 기술이 커서 나중에 검토 ([GameDesign.md](GameDesign.md)).
- 1인의 고립감은 AI 주민이 채운다 ([Npc.md](Npc.md)).

## 규칙과 수치

### 지금 지킬 것 (다인 대비)

| 규칙 | 이유 |
| --- | --- |
| 게임 상태 변경은 "명령" 함수 하나로 (`applyAction(state, action)`) | 나중에 서버가 같은 명령을 검증·재실행 |
| 무작위는 시드 있는 난수 | 서버와 같은 결과 재현 |
| 시간은 게임시간 기준(프레임 수 X) | 다른 기기와 맞춤 |
| 저장 데이터에 `playerId` 포함 ([Save.md](Save.md)) | 계정 연결 |
| 마을 데이터는 "주인 1명" 필드 | 방문 시 읽기 전용으로 보여줌 |
| NPC 기억은 플레이어별로 분리 | 다인 때 주민이 사람마다 다르게 기억 |

### 다인 전환 순서 (제안)

1. **비동기 방문**: 다른 사람 마을·집을 스냅샷으로 구경(실시간 아님). 방명록, 좋아요.
2. **편지·선물 우편**: 서버 우편함.
3. **실시간 동시 접속**: 같은 마을에 2~4명. 위치·애니메이션만 동기화, 전투는 각자.
4. 파티 전투, 거래.

- 1~2는 저장 서버만 있으면 된다(실시간 서버 불필요).

### 다인 때 고려점

| 주제 | 고려점 |
| --- | --- |
| 치트 | 브라우저 저장은 조작 가능 → 경쟁 요소(순위·거래) 전에 서버 저장 필수 |
| 철거·건축 | 남의 마을은 못 바꿈. 공용 마을은 두지 않음 |
| LLM 주민 | 여러 명이 동시에 말 걸 때 순서 큐. 비용은 사람 수에 비례 |
| 채팅 | 금칙어 필터, 신고, 차단 |
| 동기화 | 3D 위치 10회/초, 보간. Rapier 물리는 각자 로컬 |

## 데이터 모델

```ts
interface VisitSnapshot {
  ownerId: string; // 마을 주인 playerId
  ownerName: string; // 닉네임
  villageLayout: unknown; // Village/Housing 배치 데이터 (해당 문서 형식)
  look: unknown; // 주인 캐릭터 외형
  createdAt: number; // 스냅샷 시각(ms)
}
```

## 단계 (MVP → 이후)

1. **MVP**: 다인 기능 없음. 위 "지금 지킬 것"만 코드 규칙으로 지킨다.
   - 수용: 상태 변경이 모두 `applyAction`을 거친다.
2. 서버 저장 도입 후 비동기 방문.
3. 실시간 동시 접속.
