# 코드 작성 공통 규칙

코드를 작성할 때 항상 따르는 지시문이다.

## 작업 흐름

1. 관련된 기존 코드를 먼저 확인한다.
2. 이 문서의 규칙대로 구현한다.
3. 변경한 코드를 이 문서의 규칙 항목별로 하나씩 대조해 검토한다.
4. 어긋난 곳을 고치고 3단계로 돌아간다. 검토 사항이 더 나오지 않을 때까지 반복한다.
5. 변경한 동작을 테스트나 실행으로 확인하고 마친다.

## 원칙

- 일반적인 관례로 작성한다.
- UX·성능·보안·접근성·유지보수성을 고려한다.

## 구조

- 최대한 짧고 단순하게 작성한다.
- 구현 전 기존 코드를 먼저 확인하고, 최대한 재사용한다. 같은 로직을 중복해서 만들지 않는다.
- 이미 작성된 코드와 일관성 있는 규칙을 따라 작성한다. 같은 개념은 같은 이름과 패턴으로 쓴다.
- 함수 래핑, 새로운 파일 생성 등은 반드시 필요할 때만 한다.
- 함수는 한 가지 일만 하고, 인자는 적게 둔다.
- 각 폴더(constants, utils, hooks 등)는 자기 역할의 코드만 export한다.
- 컴포넌트 파일은 export하는 함수를 위에, 내부에서만 쓰는 함수를 그 아래에 둔다. 상수(와 상수가 쓰는 타입)는 import 바로 아래에, 그 밖의 타입은 쓰는 함수 바로 위에 둔다.

## 네이밍

- 변수, 함수, 파일 등은 이름만으로 의도가 드러날 정도로 명확하게 짓는다.
- boolean은 is/has/can/should 접두어를 붙인다.

## 작성 규칙

- 조건은 단순하게 쓴다. 삼항은 1단계까지만, 복잡하면 변수로 뺀다.
- 문자열·라우트·매직 넘버는 하드코딩하지 않고 상수로 분리한다.
- any 대신 unknown과 타입 가드로 타입을 좁힌다.

## 주석

- 주석은 코드로 드러나지 않는 이유만 짧게 쓴다. 무엇을 하는지는 이름과 코드로 설명한다.

## 비동기 처리

- 비동기 처리는 loading·error·empty 상태를 모두 다룬다.

## 오류 처리

- 오류를 숨기지 않고, 정상 흐름과 오류 처리를 분리한다.

## 검증

- 변경한 동작은 테스트나 실행으로 확인한다.
